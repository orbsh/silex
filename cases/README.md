# 案例集

一案例一目录，持续追加。每个案例是五阶段编译流水线（见 `../skill/SKILL.md`）的一次完整走查记录。

## 目录约定

```
cases/
└── <case-name>/
    ├── strategy.json     # 阶段 1 产物：路由判定 + 算法/特征策略
    ├── data.csv          # 阶段 2 产物：LLM 合成标注集（含难负样本变体）
    ├── truth.csv         # 阶段 4 输入：人工核验真值集（≥20 条）
    ├── gen_data.py       # 该案例的样本构造脚本（可复跑）
    ├── NOTES.md          # 流程问题账：该案例暴露的流水线缺陷与修正轨迹
    └── dist/             # 阶段 3 产物（model.onnx / embed.onnx / manifest.json）——git 忽略，train.py 可重建
```

## 规则

- 新案例 = 新目录 + NOTES.md，不改共享脚本；共享脚本的改动必须由至少一个案例的 NOTES.md 记下的缺陷驱动。
- `dist/` 不入库：资产是编译产物，输入（strategy/data）才是案例的源。
- 案例记录判定结果与门禁指标（合成一致性 / 真值准确率），失败轨迹（门禁拒绝 → 修正 → 放行）与成功同等有价值——它就是飞轮的人工版演示。
