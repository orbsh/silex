# daily-score 流程问题账

**门禁轨迹**：宽松合成标注 → 合成一致性 1.0 / 人工真值 0.83 → gate.py 拒绝（exit 1）；收紧标注口径重训（`data_strict.csv`）→ 真值 1.0 → 放行（exit 0）。模型与标注 LLM 一致 ≠ 模型与业务真值一致——双层校验存在的理由在此案例实证。

**暴露的流水线缺陷（未修，流程定案前不动共享脚本）**：

- 模态焊死：`train.py`/`lib.py` 的特征链条假设 StringTensor 文本入口，无模态轴；视觉等其他模态的流程尚未定案（见 repo 讨论：L3 嵌入器按模态选型是唯一切点）。
- 选型默认值与原则相反：`algo` 默认 `lightgbm` 是导出工具链先行验证的遗留；`matrix.md`「选型偏好」原则是优先矩阵化形态（小神经网络），代码化等流程定案。
- 案例产物入库口径：`dist/` 属编译产物不入库（.gitignore），`data_strict.csv` 这类中间产物按可重建原则同样排除在外为宜，当前未忽略。
